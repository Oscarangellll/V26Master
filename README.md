# Collaborative Offshore Wind Maintenance Planning

This repository contains the code and data pipeline used for a master's thesis on
collaborative offshore wind operations and maintenance planning under uncertainty.
The code supports scenario generation, coalition cost estimation, out-of-sample
evaluation, case studies, benefit-allocation post-processing, and thesis figures.

The repository is intended to be reproducible in two ways:

- **Quick reproduction:** use the stored CSV results in `results/` to regenerate
  tables and plots.
- **Full reproduction:** regenerate scenario data and rerun the optimization
  experiments from scratch.

The full optimization runs can be computationally expensive and require a working
Gurobi installation and license.

## Repository Structure

```text
cases/                 YAML definitions for benchmark instances.
config/                Case, scenario, sampling, and scenario-reduction configuration.
data/                  Static input data, raw/processed weather and price data, and scenario data.
data/scripts/          Data-fetching, preprocessing, scenario-generation, and parameter-building scripts.
optimization_models/   Two-stage stochastic MIP and consensus fixing heuristic.
scenario_models/       Weather and electricity-price scenario models.
results/               Stored experiment outputs used for figures and tables.
scripts/               Post-processing, utility, and HPC setup scripts.
plot_scripts/          Plotting modules and generated plot outputs.
plot.py                Main plotting entry point.
main.py                Coalition cost-estimation runner for case-study experiments.
iss.py                 In-sample stability runner.
oos.py                 Out-of-sample evaluator for ISS solutions.
stability.py           Convenience runner that executes ISS followed by OOS.
```

The thesis-writing project may be present under `texts/`, but it is not required
for running the code. Generated plots are written to `plot_scripts/plots/`.

## Environment Setup

Create and activate a virtual environment, then install the Python dependencies:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Gurobi must be installed separately and licensed for optimization runs. The
Python package `gurobipy` is listed in `requirements.txt`, but only scripts that
solve the stochastic optimization model require a working local Gurobi license.
Regenerating plots and appendix tables from stored CSV results does not require
Gurobi.

Some map plots use Natural Earth data through GeoPandas. These plots may require
internet access the first time the background map is loaded.

## Data and Scenario Generation

The model uses generated scenario data under `data/scenario_data/`. This folder
is large and may be distributed with the delivery archive. If it is absent, it
can be regenerated from the raw data:

```powershell
python init_data.py --no_fetch_weather --n_scenarios 1500
```

Use `--fetch_weather` instead of `--no_fetch_weather` to fetch fresh ERA5 weather
data through the CDS API:

```powershell
python init_data.py --fetch_weather --n_scenarios 1500
```

Fetching weather data requires valid CDS API credentials. The generated scenario
data are used by the optimization runs, validation plots, and case studies.

## Quick Reproduction from Stored Results

Regenerate thesis plots from the stored result files:

```powershell
python plot.py thesis
```

Useful plot groups:

```powershell
python plot.py --list
python plot.py method
python plot.py data
python plot.py case
python plot.py appendix
python plot.py diagnostic
```

Individual plots can also be generated by name:

```powershell
python plot.py stability
python plot.py case_studies
python plot.py weather_validation
```

Regenerate appendix result tables from stored outputs:

```powershell
python scripts/make_appendix_tables.py
```

The generated figures are written to `plot_scripts/plots/`. Generated summary
tables are written to `results/appendix_tables/`.

The `diagnostic` plot group contains additional analysis plots that were useful
during model assessment but are not part of the default thesis plot group.

## Full Experiment Reproduction

### Stability and Method Assessment

Run ISS and OOS for a benchmark case:

```powershell
python stability.py -c 2W2B -m con_mp -n 20 -s 1 3 5 7 10 15 20
```

Use `-m mip` for direct MIP solves on smaller instances:

```powershell
python stability.py -c 2W2B -m mip -n 20 -s 1 3 5 7 10 15
```

The default output paths are:

```text
results/stability/<case>/<method>/ISS.csv
results/stability/<case>/<method>/OSS.csv
```

Stratified sampling experiments can be run by selecting the stratified sampling
strategy and writing to explicit output files, for example:

```powershell
python stability.py -c 2W2B -m con_mp -n 20 -s 1 3 5 7 10 15 20 `
  --sampling_strategy stratified_bins `
  --kindness_metric count_location_days_over_threshold `
  --kindness_ww_threshold 8 `
  --iss_output results/stratified/con_count_over_8_ISS.csv `
  --oos_output results/stratified/con_count_over_8_OSS.csv
```

### Base Case Study

Run coalition cost estimation for all coalitions in the reference case:

```powershell
python main.py `
  --actors A B C D E F `
  --bases 3 5 6 7 `
  --max-multiday-vessels 6 `
  --num-nodes 1 `
  --node-id 0 `
  --n-scenarios 15 `
  --scenario-start 1 `
  --scenario-end 500 `
  --seed 20 `
  --method con_mp `
  --sampling-mode shared `
  --output results/case_studies/base/iss.csv
```

Evaluate the resulting first-stage solutions out of sample:

```powershell
python case_study_oos.py `
  --input results/case_studies/base/iss.csv `
  --case-id base `
  --bases 3 5 6 7 `
  --oos-start 501 `
  --oos-end 1500 `
  --coalition-output results/case_studies/base/coalition_oos.csv `
  --windfarm-output results/case_studies/base/windfarm_oos.csv
```

### Distance and Turbine-Count Case Studies

Generate the distance-case failure data:

```powershell
python case_study_distance_failures.py
```

Run and evaluate the distance cases:

```powershell
python case_study_distance_iss.py
python case_study_distance_oos.py
```

Run and evaluate the turbine-count cases:

```powershell
python case_study_n_turbines_iss.py
python case_study_n_turbines_oos.py
```

These scripts write to `results/case_studies/distance/` and
`results/case_studies/n_turbines/`.

## Parallel and Distributed Runs

Several runners support `--num-nodes` and `--node-id`. This allows a coalition
set to be split across multiple processes or machines. For example, with four
nodes, run the same command four times with `--node-id 0`, `1`, `2`, and `3`,
then merge the node-level CSV files if needed.

```powershell
python scripts/merge_case_study_results.py `
  --input-dir results/case_studies/base `
  --pattern "iss_node_*.csv" `
  --output results/case_studies/base/iss.csv
```

The file `scripts/setup_hpc_env.sh` gives an example of the module and
environment setup used on the NTNU HPC system.

## Notes for Future Development

- Stored `results/` files allow figures and tables to be regenerated quickly.
- Full optimization experiments may take a long time, especially direct MIP
  runs for larger instances.
- `data/scenario_data/` is large. Keep it with the delivery archive if the
  recipient should be able to run experiments immediately without regenerating
  scenarios.
- The plotting code is intentionally centralized through `plot.py`; individual
  plotting modules can still be run directly for debugging.
